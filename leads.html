Production CRM Activation Guide

To activate a secure, authenticated leads management system for Neha Infrastructures staff, deploy a server-side backend such as Supabase with Row Level Security (RLS) and email authentication.

  • Server-Enforced Authentication: Use Supabase Auth or OAuth with corporate email domain restrictions (`@nehainfra.com`). Never embed administrative passwords in static client code.
  • Row Level Security (RLS) Mandatory: The public website client only receives a write-only permission (`INSERT`) to submit leads. The read, update, and export permissions (`SELECT`, `UPDATE`, `DELETE`) are strictly denied to unauthenticated visitors.
  • Strict Secret Isolation: Keep database connection strings and `service_role` secret keys out of source control. Only the restricted public anonymous key (`anon_key`) may be referenced in frontend configuration.

Recommended PostgreSQL RLS Schema:

-- 1. Create secure leads table CREATE TABLE public.leads ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), created_at TIMESTAMPTZ DEFAULT NOW(), client_name TEXT NOT NULL, phone TEXT NOT NULL, email TEXT, service_category TEXT, scope_details TEXT NOT NULL, status TEXT DEFAULT 'New' ); -- 2. Enable Row Level Security ALTER TABLE public.leads ENABLE ROW LEVEL SECURITY; -- 3. Public policy: Allow anonymous visitors to insert new enquiries ONLY CREATE POLICY "Allow public enquiry submission" ON public.leads FOR INSERT TO anon WITH CHECK (true); -- 4. Admin policy: Allow authenticated Neha staff to view and manage leads CREATE POLICY "Allow authorized staff management" ON public.leads FOR ALL TO authenticated USING (auth.jwt() ->> 'email' LIKE '%@nehainfra.com');
